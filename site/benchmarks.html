Public API rows build the env exactly the way a user does: mg.make(mg.robots.walker()), mg.robots.tripod(), mg.robots.hopper(), with random actions. Training (sim + PPO) is end-to-end mg.train: rollout, advantage estimation and gradient updates, first (compile) iteration excluded. That is the number that decides how long training takes. Hand-written env rows are the original fixed-morphology envs, sim only.

Why small batches look the same

At 1,024 envs the numbers don't track robot complexity; an earlier run had walker and cheetah at 752K and 746K env-steps/s. The GPU is not the bottleneck there: each step pays a roughly fixed cost for Python and MLX graph dispatch, whatever the robot. As the batch grows that cost is amortized, the GPU saturates, and throughput starts to reflect the actual physics work. Run-to-run noise on a busy laptop also shows up most at small sizes.

Limitations

Not the same solverBoth sides are planar for locomotion: MuJoCo's HalfCheetah is constrained to the x-z plane too. The real difference is the solver. MuJoCo integrates generalized coordinates with a convex, constraint-based contact solver. MacGym uses maximal coordinates (each body has its own position and angle) with a simpler sequential-impulse contact solver and a few substeps. Read the ratios as how much RL experience per second this laptop generates for these tasks, not as MLX beating MuJoCo at identical simulation.
  • The MLX walker has no MuJoCo twin, so it is compared against the HalfCheetah-like model as the nearest planar locomotion model.
  • MuJoCo numbers come from a plain Python mj_step loop, so they include Python overhead per step. One process per core uses all P and E cores.
  • The laptop was not idle. GPU numbers vary by roughly ±30% run to run, and the CPU rows can drop up to 2x when other jobs share the cores, which inflates the ratios. The load average is recorded with every run.
  • Env-steps per second counts control steps summed over all environments, with physics substeps and frame-skip included.

Method

MLX: median of 5 timing windows, random actions generated on the GPU, full mx.eval every step, auto-reset included, mx.compile on the physics step. Training row: a short mg.train run at 4,096 envs, env-steps consumed divided by wall time after the first iteration. MuJoCo: Gymnasium-style models written inline (InvertedPendulum-like cartpole with timestep 0.02 and frame skip 2; HalfCheetah-like planar model with timestep 0.01 and frame skip 5), random controls, then one process per core with spawn, warmed up. Raw numbers and notes are in web/bench.json.
