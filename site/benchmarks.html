Caveats

Not the same physicsMacGym uses its own simplified 2D planar dynamics: capsule bodies, maximal coordinates, penalty ground contact, a few substeps per control step. MuJoCo solves full 3D generalized-coordinate dynamics with a constraint-based contact solver. Read these ratios as how much RL experience per second this laptop can generate for these tasks, not as MLX beating MuJoCo at identical simulation.
  • The MLX walker has no MuJoCo twin, so it is compared against the MuJoCo half-cheetah as the nearest planar locomotion model.
  • MuJoCo numbers come from a plain Python mj_step loop, so they include Python overhead per step. One process per core uses all 11 P and E cores.
  • GPU numbers varied by roughly ±30% run to run. The laptop was not idle during measurement; other training jobs shared the GPU.
  • Env-steps per second counts control steps summed over all environments, with physics substeps and frame-skip included.

Method

MLX: median of 5 timing windows, random actions generated on the GPU, full mx.eval every step, auto-reset included, mx.compile on the physics step. MuJoCo: Gymnasium-style models written inline (InvertedPendulum-like cartpole with timestep 0.02 and frame skip 2; HalfCheetah-like planar model with timestep 0.01 and frame skip 5), random controls, then one process per core with spawn, warmed up. mlx 0.32.4, mujoco 4.0.1, Python 3.13.12.
